# Keyhide 1.0.1 本地优化

## 交付约束

- 仅在本地修改、验证和构建 Windows 安装版与便携版。
- 不提交 Git commit、不推送、不创建 PR。
- 使用 1.0.1，用户确认满意前不得升至 1.1.0。
- 保留 OpenAI / Anthropic / 自定义平台的透明转发能力，不更换产品定位或接入供应商。

## 设计方向

Keyhide 的任务是让真实密钥留在本机，并让开发者清楚知道请求被送往哪里。界面采用“本地连接工作台”，以连接链路和可执行操作为中心，而不是把所有信息堆成仪表盘卡片。

### 视觉系统

- 深蓝底色 `#101b2c`：工作空间。
- 蓝灰表面 `#16243a`：配置与列表。
- 分隔线 `#30425f`：结构层级。
- 冰蓝强调 `#79b8ff`：当前导航和主要动作。
- 明亮正文 `#eaf1fb`：内容与数值。
- 次级文字 `#a4b5ce`：说明；状态配色与图标、文字一起使用。

字体采用本机 Segoe UI Variable / Microsoft YaHei UI，接入地址与代码采用 Cascadia Code / Consolas；不加载远程字体。24–32px 页面标题、14px 正文、12px 辅助内容。内容左对齐，表单说明保持短行。

### 布局

```text
┌─ 原生窗口标题栏 ───────────────────────────────────────┐
│ Keyhide / 本地工作空间                  连接状态        │
├─────────────┬─────────────────────────────────────────┤
│ 品牌        │ 页面标题                     主要动作    │
│ 工作台      │                                         │

│ 模型目录    │                                         │
│ 代理服务    │ 上下文说明、错误恢复、相关操作           │
```

工作台展示实际连接链路与首次配置引导。平台管理采用可展开条目，模型目录独立为可搜索、按平台筛选的分页列表。代理页面清楚区分 OpenAI 的 `/v1` SDK 地址与 Anthropic 的根地址。设置保存、密钥修改、导入与删除均有明确反馈和风险提示。

### 设计审视

不使用泛化的紫色渐变、发光 Logo、四张同规格彩色大数卡或无意义动效。最具辨识度的部分是本机凭证与真实上游之间的连接链路，其余采用安静的表单和列表结构。统计明确写出“保留日志”，不把截断的日志数量称作累计总请求。

## 收尾修复

- 后端通过 IPC 提供临时 Key 的冷却截止时间，界面在到期时自动刷新；重启后可恢复的 Key 不再把启动、模型获取和可用模型筛选永久锁住。
- 编辑器接受后端支持的查询参数、小数权重与额度、负数整数优先级；保存数字配置后统一规范化草稿。
- 编辑草稿携带来源快照，后台刷新后的普通保存不会错误恢复被 401 禁用的 Key。
- 启动期间锁定监听配置，关闭日志记录时仍更新运行统计；被替换上游的旧模型获取结果不会覆盖新配置。
- 日志在保存和发送前遮蔽配置凭证、编码查询参数和自由文本中的密钥，删除凭证后不会使新记录重新暴露密钥。
- 压缩 JSON/SSE 进行有界用量解析，中断流保留已经观察到的用量；HTTP 200 中的 SSE 错误事件按失败记录。

## 边界

配置延续原有机器/用户/salt 派生的 AES-GCM 格式，不是操作系统密钥库。接入 Key 和明文配置导出仍然是敏感凭证。Token 记录是估算，JSON/压缩正文观察上限 5 MiB，单个 SSE 事件上限 512 KiB；超出范围或缺失上游用量时无法保证完整统计，不应将本地上限作为严格费用限制。Windows 构建没有配置代码签名证书，系统可能显示发布者或 SmartScreen 提示。macOS/Linux 未进行打包验证。
